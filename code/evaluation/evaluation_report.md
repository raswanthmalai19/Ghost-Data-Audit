## 2. Method

* **Ground truth** - `dataset/sample_output.csv` (32 rows) is the only labelled data. It is used for measurement only: no case id, resource id or answer from it appears in the code, and the 518 evaluation rows are produced by the same code path.
* **Step tuple** - a step is compared as `(phase, system_id, resource_id, operation, state, evidence_id)`; `step_no` is implied by order. JSON key order and whitespace are ignored, as by the official grader.
* **Case metrics** - status accuracy; exact match requires the status and the full ordered step list to be identical.
* **Step metrics** - micro-averaged multiset precision/recall/F1 over step tuples across all cases.
* **Field metrics** - (a) *aligned*: each gold step is matched to the predicted step with the same `(phase, system_id, resource_id)`, then each field is compared (a missing step counts as wrong on every field); (b) *positional*: step *i* vs step *i*, which also penalises any shift caused by a missing or extra step.
* **Sequence accuracy** - share of cases whose steps common to gold and prediction appear in the same relative order.
* **Ablations** - each pipeline component can be switched off (`EngineConfig`) to measure its contribution.
* **Synthetic suite** - `evaluate.py` writes an independent mini-dataset (6 users, new resource ids, a log, two JSON exports, a regional-replica SQL dump, a rendered PNG screenshot read by OCR, a late snapshot) and checks the full pipeline end to end.
* **Full-dataset diagnostics** - the 518 evaluation rows have no labels; we report structural checks (contract validity, status mix, attribution ambiguity) instead of accuracy.
